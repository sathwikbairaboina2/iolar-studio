A local pipeline that turns a topic, a pasted script, or someone else’s reel into a finished 1080×1920 vertical video — script, voice, footage, cuts, captions and encode — with a browser studio to watch and fix the edit while it renders. 00 What it is

One reel is a folder. Six stages fill it in, each one writing a file the next stage reads. Nothing is held in memory between stages, so any stage can be re-run alone and the studio can open a reel that is half-finished.

The engine lives in the iolar-reels worktree on branch feat/reels-engine, alongside the handbook studio but sharing none of its storage. It is a category inside the same Next.js app: same server, same settings file, its own route tree under /reel.

Rule, revised 2 September

The first edition said a reel writes nothing to the knowledge graph. That is retired: reels, handbooks and jobs each write to their own space of one Neo4j graph, through lib/knowledge/ and nowhere else (section 19). What stands: saveReel() still writes one JSON file and stops, the reel folder is still the truth, and no reel path touches SQLite. The stores are derived and rebuildable.

The shape of a run

You give it one of three things — a topic, a finished script, or the URL of a reel you like. It writes beats, speaks them, produces footage for each one, cuts the footage to the voice, hands you a studio to fix what it got wrong, and encodes an MP4. Since this edition a fourth entry sits in front of the others: a brief, which the research stage (section 16) turns into a sourced, verified, approved script before any beat is planned.

04 Stage 1 · Plan

Three entry points, one code path. Whatever the source, the output is beats: a spoken line and a footage brief per shot.

On POST /api/reel/[slug]/plan

1planFromTopic | planFromScript | planFromReferenceChosen from body.mode: topic, paste, reference
2fetch(mediaUrl) → transcribe(dest)Reference mode only. Saves refs/reference.mp4, whisper writes refs/transcript.txt
3loadReel(slug) → loadPattern(reel.pattern)The pattern supplies the voice, the shot-second range and the shot mix
4beatsPrompt(pattern, mode, source)Assembles task + voice + pacing + mix + the JSON shape contract
5runClaude(prompt, { timeoutMs: 900000 })Claude CLI as a subprocess. 15 minutes, because a long script is a long think
6parseBeats(raw)Extracts JSON from possible prose, backfills ids, rejects empty text and duplicate ids
7checked(mode, source, out)Paste mode only: wordingDrift() throws with the exact clause where the beats stop matching
8runClaude(… + validation error)One retry, feeding the failure back in. A second failure is the caller’s problem
9applyPlan → saveReel(slug, next)Writes title, beats and post caption. Timeline untouched

Pacing is derived, not guessed. From the pattern’s shotSec range the prompt computes a word budget at roughly 2.6 words per second, asks for 8–14 beats, and states the target mix of screen, talking-head and b-roll shots along with how often to return to an anchor.

Why wordingDrift exists

Paste mode promises the script comes back word for word — that is the entire reason to paste one. Nothing enforced it, and a re-split silently duplicated a clause across two beats. The check is whitespace-insensitive and otherwise exact, and reports the first divergence with 40 characters of context on either side.

06 Stage 3 · Shots

Every beat gets footage, but not from the same place. The routing decision is the single most consequential one in the engine, and it is made by shot.kind.

Since the first edition

The ComfyUI image-to-video adapter described above is gone from this worktree. Generated shots go through video providers the user built and owns: lipsync for talking heads (a Celery queue in front of ComfyUI on :8300) and webpage-mp4 for page shots (:8080). They are registered in lib/reel/providers/, watched from the Plugins page (section 17), and the lipsync provider hands the GPU over before it posts a job.

On POST /api/reel/[slug]/shots

1planShots(slug)Walks beats, decides a producer per beat, writes placeholder assets with status: 'queued'
2runShots(slug)Executes the plan. Screen and title beats run inline; generated beats are submitted and polled
3scenePrompt(brief)Strips anything the model would render as literal on-screen text before it reaches the prompt slot
4writeParameterisedWorkflow(…)Copies the MiniMax H3 template and sets slots by subgraph address (114.image, 105/104.prompt, 105/15.noise_seed, 115.aspect_ratio)
5animateImage → parsePromptIdSubmits via comfy-cli, keeps the prompt id for polling
6jobState(promptId)Polls the ComfyUI history endpoint until the output appears or it errors
7pickVideoOutput → collectVideoCopies the file out and trims GENERATED_LEAD_IN_SEC = 0.6 from the head
8attachAsset(slug, beatId, file, role)Registers the finished file against its beat and flips status to ready
9refreshShots(slug) / retryShot(slug, id)GET re-polls anything still running; retry re-runs one beat with a new seed
The 0.6 second lead-in

Generated clips opened on a frame from an earlier job — roughly six tenths of a second of the wrong image before the right one. Rather than fight the queue, collectVideo trims a fixed lead-in on the way out. The constant is named and exported so the assemble stage knows the usable footage is shorter than the file.

Recording a scene

Screen footage is not a screen recording of a real app and not a diffusion output. It is an HTML page in scenes/ that exposes window.SCENE.frame(p), driven one frame at a time by Playwright and encoded from stills. Deterministic, re-recordable at any length, and pin-sharp at 1080×1920.

07 Stage 4 · Assemble

The cut is derived, not authored. Beats give the wording, whisper gives the clock, the asset pool gives the pictures, and the pattern gives the pacing.

On POST /api/reel/[slug]/assemble

1loadReel(slug)Bails out early if timeline.locked; a manual edit outranks a re-assembly
2beatSpans(beats, words)Maps each beat onto a start and end in the voiceover by matching its words in sequence
3scriptAlignedWords(beats, words)Pairs script tokens with ASR tokens, keeping the script’s spelling and the ASR’s times
4groupCaptions(aligned, wordsPerBeat)Chunks into cues sized by the pattern, enforcing MIN_CUE_SEC because whisper emits words where start equals end
5piece walk: pool[p % pool.length]Splits each beat span into shot-length pieces and assigns footage, cycling the beat’s own asset plus its alsoAssetIds
6motion assignmentStills get a ken-burns move scaled by SCREEN_MOTION_GAIN; recorded and generated video gets HELD
7saveReel(slug, next)Clips are written contiguous — end of one is start of the next, no gaps to render as black
Why video is HELD

Applying a ken-burns move to recorded UI footage cropped the frame and cut words in half — an invoice list rendered as “oices”. Motion exists to give a still life. Footage that already moves gets none, which is what HELD means.

08 Stage 5 · Studio

The studio at /reel/[slug] is deliberately small: a phone-shaped preview, a timeline strip, and about a dozen operations. Everything else is autonomous. What it must get right is that the preview and the export agree.

Preview parity

The preview is not a video — it is the timeline played in the DOM, positioning a <video> or <img> per clip and drawing captions as HTML. Two renderers producing the same picture only works if they share the arithmetic, so they do.

Caption sizing needed the same treatment for a different reason. Sizes expressed in vh resolved against the browser window in the preview and against the 1920px frame at export — captions came out roughly twice the intended size. Pattern CSS now emits container-query units (cqh) with container-type: size on the frame, so both renderers measure against the same box.

Edit operations

Every one of these sets timeline.locked = true. That flag is the contract between you and the engine: once you have touched the cut, re-assembly will not overwrite it.

OperationDoesRipple
trimClipChanges a clip’s durationFollowing clips shift; timeline stays contiguous
splitClipCuts one clip into two at the playheadSecond half inherits srcIn plus the offset
deleteClip / moveClipRemoves or reordersStarts recomputed from zero
setClipMotion / setClipFit / setClipTransitionPer-clip lookNone — timing untouched
replaceClipAssetSwaps the footage under a clipNone — the hole in the cut stays the same length
editCaption / toggleCaptionRewrites or hides a cueNone
nudgeCaptionShifts a cue in timeNeighbours clamp, cues never overlap
mergeCaption / splitCaptionJoins or divides cuesSpan of the pair is preserved
reflowRecomputes contiguous starts across the whole timelineThe repair operation after a batch of manual edits

Watching it render

POST /export returns a text/event-stream. The route wraps exportReel(slug, onProgress), and progress comes from ffmpeg’s own -progress output rather than an estimate: parseProgress() reads out_time_ms against the known timeline duration. Percentages are only emitted when the whole number changes, so the stream is quiet, and the final frame carries { done: true, path, durationSec }. The DOM preview stays fully usable throughout, because nothing about the preview depends on the encoder.

09 Stage 6 · Export

One ffmpeg invocation. Every clip becomes its own filter chain, the chains concatenate, captions composite on top, and the voice runs a separate chain into the same mux.

On exportReel(slug, onProgress)

1loadReel(slug)Timeline is the source of truth; the beats are not consulted again
2renderOverlays(slug, pattern)One PNG per visible cue, written into overlays/ by Playwright from the pattern’s caption.css
3measureLoudness(vo.wav)First loudnorm pass. parseLoudness() reads the JSON ffmpeg prints to stderr
4loudnormFilter(measured)Second pass gets the measured values, which is what makes the target reachable instead of approximate
5buildExportArgs(reel, paths)Builds the whole graph as an array. Pure and unit-tested — the argument list is asserted, not the output file
6spawn ffmpeg … -progress pipeparseProgress() converts out_time_ms into a fraction of the known duration
7onProgress(pct)Route rounds to whole percent and pushes an SSE frame only on change
8return { durationSec }Route sends { done: true, path: 'export/reel.mp4' } and closes the stream

Loudness

Target is -14 LUFS with an LRA ceiling of 20. The first attempt landed at -15.3 and would not move: a 25 dB crest factor kept loudnorm in dynamic mode, where it declines to apply the gain it calculated. Compressing and limiting before loudnorm brings the crest down, and the measured result is -14.78 LUFS. VOICE_CHAIN is that pre-chain, exported as a constant so the test can assert its order.

Byte ranges are not optional

How each is measured

  • Shots — ffmpeg scdet at threshold 0.4, the same detector used by clonePattern, so the reference and the output are judged identically.
  • Black and frozen — blackdetect and freezedetect. Both once fired on real defects: a scene that emptied out for 2.6 seconds, and three frozen stretches where footage shorter than its slot held its last frame.
  • Loudness — loudnorm’s own print pass, parsed by parseLoudness().
  • Caption sync — each cue’s start compared against the aligned word it begins with, reported as median and p90.
  • Caption band — frame sampling, identical code path for both files.

Test suite

The interesting ones are not the unit tests: reel.parity.test.ts asserts the preview and the export agree on motion, reel.ffmpeg.test.ts asserts the argument array rather than the encoded file, and reel.paths.test.ts guards the disk layout every other module assumes.

One measurement worth keeping

The turbo LoRA made generation slower, not faster: 595s against 351s, because a bf16 LoRA sits on an int8 base. i2vTurbo stays false in settings, and the number is recorded here so nobody re-tries it on the assumption that turbo means turbo.

15 Limits & next

Known gaps

  • Shot count. Ten detected cuts against the reference’s eighteen. The scenes are visually consistent by design, and the detector reads consistency as continuity. More distinct scene grounds, or a deliberate cut-away vocabulary, is the lever.
  • Loudness range. 2.0 LU against 3.1. Kokoro does not push a phrase for emphasis, so the delivery is even. Real narration would close this without touching the engine.
  • Talking heads. Generated rather than filmed, and it shows on close shots.

Deliberate non-features

  • No knowledge-graph writes outside lib/knowledge/. The old rule, no writes at all, is retired as of 2 September; the new one is one door.
  • No headless Claude for research. The local model, or nothing.
  • No Higgsfield in the current path. The client exists and is gated behind hfAvailable(); nothing calls it.
  • No cloud anything. A reel can be produced with the network off, once the models are on disk.
  • No timeline autosave loop. Edits write on the operation, and locked makes that decision permanent.

Running it

npx next dev --webpack -p 3120 in the iolar-reels worktree. --webpack is required: an Application Control policy blocks the SWC binary and Turbopack refuses WASM bindings. The research service is the opposite and runs on plain Turbopack. Then:

16 Research

Added after the first edition. Before a reel has a script it has a brief, and before it has a brief it has nothing a model should be trusted with. The research stage turns a brief into a script whose every line cites a source that survived a person’s review, and it runs entirely on the local model.

Hard rule

Research runs on qwen3.8:27b through the research service, never on headless Claude. The Claude path still exists behind the researchProvider setting, but local is the default and the only path that is tested. Nothing leaves the machine and nothing is billed. Every strategy is shown before it runs and every search is shown as it happens — a source pack with no visible strategy behind it is not one to trust.

On POST /api/reel/[slug]/research/run, one advance

1{ brief }First call carries the wizard’s brief: topic, angle, audience, two to five claims to prove, names to include, things to avoid, source classes. Status becomes briefed
2planSearch(brief)Writes an approach and one query per claim, each tagged with what it proves and why. Status planned, gate: the plan is shown and editable
3{ plan } → huntLocally(armed, plan)POSTs the composed question and the approved plan to the research service, polls the run, mirrors each search and read into trace.json. Up to 900 seconds
4critique(brief, found)The adversarial critic: keep, maybe or reject each source with a reason. Rows it shapes wrong are dropped and counted, not fatal. Status critiqued, gate: review
5PUT /research/selectionYour decisions. Keeping nothing is refused here rather than three stages later. Status reviewed
6gatherEvidence(kept)Fetches page text or a yt-dlp transcript per kept source into evidence/<id>.json. No video is downloaded
7draftScript(brief, kept, evidence)Lines with roles and citations, written from the evidence, not the summaries
8verifyScript(lines, evidence)Every cited line is read against passages of its source, numbers first. A flag names the line and the objection
9revise, then verify againOne round. Flags that survive it are shown on the script, they are not hidden
10judgeCoverage(mustProve, lines)Which line proves which claim; a claim nobody proves is listed as unsupported. Status drafted, gate: approval

The gap this exposes

pageText() keeps the first 20,000 characters of a page and the writer sees only the first 4,000 of that. NIST SP 800-63B is 354 KB; the section about memorized secrets never reached the evidence file, so the verifier was right to flag lines that were, in fact, true. The knowledge layer in section 19 closes this: passages are chunked from the whole page and the verifier is handed the three nearest by meaning.

The research service

The hunter is a separate Next app, research-plugin, on 127.0.0.1:25100: a tool-calling loop on the same qwen, with channels for searxng, a reader, yt-dlp, gh and RSS, and its own docker side (ollama on 25103, searxng on 25180). It accepts a plan, caps tool calls, and writes a report with sources. The studio never reads its disk; it polls GET /api/research/<id> and mirrors each step into the trace panel the Research tab shows.

Every card is one entry in lib/plugins/registry.ts: name, port, health URL, one line of purpose, an open link, and a start recipe the server runs by name. Nothing a caller sends is ever executed; the recipe comes from the registry. Health is probed in parallel with a six-second budget so a slow service cannot hold up the page.

Handing the GPU to ComfyUI

One RTX 4090, 24 GB. qwen3.8:27b occupies 16.2 GB of it while the research ollama holds it loaded, and a lipsync render needs most of that back. So before the lipsync provider posts a job it calls yieldGpuToComfy(), which asks research-ollama what it holds and unloads each model with keep_alive: 0. VRAM is free within a second. The next research call reloads qwen, about half a minute later.

1GET :25103/api/psWhat is loaded, with size_vram. Ollama down means ollama holds no VRAM, so the render proceeds
2POST :25103/api/generate { model, keep_alive: 0 }Per model. Logged as “ComfyUI render coming: unloading qwen3.8:27b (16.2 GB) from research-ollama”
3POST :8300/jobsOnly now. A failure in steps 1 or 2 is logged and swallowed; a render is never refused for it
Not guarded

A hunt that runs at the same moment as a render reloads qwen mid-render. The hand-off is one direction: ComfyUI wins when it starts, nothing stops research from starting after. If that bites, the fix is a “research busy” check that refuses the render with a clear message, not a lock.

Everything on screen

All of this happens on the server, so it writes a line to a ring buffer of 200 entries (lib/plugins/log.ts). PluginActivity, mounted in the root layout, polls GET /api/plugins/log?since= every three seconds and raises each new line as a notification wherever you are in the studio; errors stay until dismissed. The Plugins page lists the same feed under “What the plugins are doing”. Starts, hand-offs, and services going down or coming up all land there.

A state has to hold for two polls before it is announced. The research service’s own health check takes one to three seconds and now and then crosses the budget, and one timed-out poll announced as an outage, then retracted three seconds later, is noise nobody can act on.

19 Knowledge layer

Designed 2 September, implementation next. The single SQLite graph is replaced by Neo4j with one space per category, and Qdrant holds the text the agents need to find by meaning. The point is not the picture on the graph page. The point is that the research agents stop starting every hunt from zero.

Rule change

The first edition of this handbook said a reel writes nothing to the knowledge graph. That rule is retired by the user’s decision on 2 September. Reels, handbooks and jobs each write to their own space of one graph, through lib/knowledge/ and nowhere else. What has not changed: files on disk are the truth, both stores are derived, and one command rebuilds them.

Topics use the same topicKey() normalisation as before, so a chapter on slicing and a reel on slicing collide on one node. That collision is the All tab: nodes whose neighbours carry more than one space, with those neighbours. No edge is invented for it.

What each agent gets, phase 1

1planner ← domainsFor(topics)Up to 12 domains ranked by kept minus rejected on sources about these topics, and up to 6 flagged as walled. “ccaf.io kept 3, rejected 0. Avoid iea.org: bot wall.”
2critic ← priorVerdicts(urls)For each hunted URL already known: last verdict, reason and reel. The critic keeps its own judgement but is told the page was a duplicate last time
3writer ← provenClaims(mustProve)Claims near each mustProve with at least one SUPPORTED_BY, with passage and source. A prior source is citable only if it is also in this reel’s kept set; otherwise it becomes a suggested query
4verifier ← passagesFor(line, keptIds)Top three chunks by meaning, scoped to this reel’s kept sources, ahead of the keyword windows. The page cap rises to 200,000 characters; only the prompt window stays small

Every block is capped in characters and count, and the tests hold the caps. The Claude provider path gets none of this and keeps working as before. knowledgeMemory: false in settings turns recall off and the pipeline behaves exactly as it did in the table above.

Phases 2 and 3

  • Script and style. A scripts collection and ScriptLine.approved. The planner learns which angles were already used on a topic and which hooks were approved.
  • Cross-category. A chapters collection. The writer’s proven claims also return the handbook chapter near a claim and the jobs week that highlighted the topic; a script line may cite a chapter, shown as a “see the handbook” card.

The page

/graph keeps one sidebar entry and grows tabs: Handbooks, Reels, Jobs, All. Each tab is one Cypher query capped at 400 nodes, most-connected first, drawn with cytoscape and the fcose layout; the hand-rolled radial SVG goes, along with the bug that made it filter for a node type the handbooks migration had renamed. The search box matches labels. A second box, “ask by meaning”, runs the Qdrant search on that space and shows the hits with scores, which is how you see what the agents would see.
